# Инструкции для Codex: РИ-фест

## Источники

Перед работой прочитай [ТЗ](docs/ri_fest_tz_roadmap_v03.md), нужную задачу в [плане](docs/ri_fest_codex_plan_v1.md) и связанные разделы [архитектуры](docs/architecture.md). Команды запуска — в [README](README.md), тексты и изображения — в [материалах фестиваля](docs/ri_fest_2027_content_seed.md). Явные указания пользователя имеют приоритет.

## Разработка

- Выполняй запрошенную задачу; следующие этапы и посторонние рефакторинги не начинай без просьбы.
- Используй Django Templates, Forms/ModelForms, стандартную Admin, обычный CSS и JavaScript. Сохраняй фирменный адаптивный дизайн, общие шаблоны и переменные темы. Отдельные SPA и REST API не планируются; новые зависимости и изменения архитектуры сначала обоснуй и согласуй.
- Бизнес-правила описаны в ТЗ. Не выбирай самостоятельно неоговорённые решения об оплатах, архивах, правах и уведомлениях — уточни их у пользователя.
- Запускай проект и проверки через Docker. Python задан в Dockerfile, зависимости — в requirements.txt. Локальное окружение PyCharm без необходимости не меняй.
- Не добавляй секреты в Git. Для тестов используй только вымышленные данные.

## Проверки

- Добавляй тесты на изменяемые правила и выполняй проверки соответствующей задачи. Не удаляй падающие тесты ради успешного результата.
- Проверяй изменённый интерфейс в браузере. В результате перечисляй выполненные проверки и причины, если что-то не запускалось; не выдавай запланированное за проверенное.

## Git и отображение изменений

- Не выполняй commit, push, merge, rebase, создание или удаление веток без явной просьбы. Если просят составить коммит, изучи состояние Git и все фактические изменения, затем предложи сообщение на английском в формате Conventional Commits. Сам коммит не создавай.
- Файлы проекта создавай, редактируй, переименовывай и удаляй только встроенным apply_patch: один файл за вызов, без других операций в том же вызове. Не записывай правки через терминал, IDE-инструменты или форматтеры с перезаписью.
