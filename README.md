# РИ-фест

Сайт регистрации на Сибирский фестиваль ролевых игр «РИ-фест».

Django и PostgreSQL, серверные шаблоны и формы, стандартная Django Admin, обычный CSS и JavaScript.

## Запуск

Нужен Docker Desktop с Linux-контейнерами. Создайте `.env` по образцу [.env.example](.env.example) и заполните `DJANGO_SECRET_KEY`, `DB_PASSWORD` и `POSTGRES_ADMIN_PASSWORD`. Пароли базы должны различаться; значения со знаком `$` заключайте в одинарные кавычки.

```powershell
docker compose --profile dev-mail up --build -d
```

Сайт: <http://127.0.0.1:8000/>. Миграции применяются автоматически. После изменения кода повторите команду запуска.

Локальные письма подтверждения email и восстановления пароля: <http://127.0.0.1:8025/> (Mailpit). Письма не отправляются во внешнюю почту; при пересоздании Mailpit они могут удалиться. Профиль `dev-mail` нужен для ящика разработки; приложение не зависит от него при работе с другим SMTP.

В `ri_fest/settings.py` настройка `EMAIL_VERIFICATION_REQUIRED = False` разрешает автоматический вход после регистрации без подтверждения email. При `True` новый аккаунт сначала подтверждает адрес. Настройка не связана с DEBUG или env; старые аккаунты не требуют повторной активации. Вход без подтверждения не отмечает адрес подтверждённым.

Во вкладке «Личные данные» можно изменить email с текущим паролем, увидеть статус подтверждения и повторно отправить письмо. При `False` новый адрес сразу становится логином; при `True` до подтверждения нового адреса вход и восстановление пароля работают по прежнему. Ожидающую смену можно отменить. Изменение настройки само по себе не применяет ранее созданные запросы смены email.

`docker compose down` останавливает контейнеры, сохраняя данные в томах. PostgreSQL работает внутри Docker; локальная установка не нужна. Изменение пароля в `.env` не меняет пароль уже созданной роли базы.

## Проверки

```powershell
docker compose exec web python check.py
docker compose --profile test run --rm tests
docker compose exec web python manage.py makemigrations --check --dry-run
```

`check.py` запускает Django check, pytest и Ruff, включая проверку форматирования без перезаписи. Обычные тесты используют SQLite в памяти; сервис `tests` в профиле `test` проверяет отдельную PostgreSQL-базу `ri_fest_test`, общие счётчики Redis и отправку писем по SMTP через Mailpit.

## Настоящая почта

Заполните почтовые параметры из `.env.example` значениями вашего SMTP: сервер, порт, логин, пароль, TLS/SSL и адрес отправителя. TLS и SSL одновременно не включаются. Затем пересоздайте контейнеры командой запуска. Формы и письма менять не нужно; проверьте доставку в реальный ящик и адрес сайта в ссылках. При развёртывании Mailpit не требуется.
